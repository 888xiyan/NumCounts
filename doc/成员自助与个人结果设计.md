# 成员自助与个人结果设计

## 1. 目标

M6 让 `USER` 角色能够读取管理员已发布的规则插件和工作流、运行个人试算，并查看和导出自己的已复核正式绩效。成员不能创建、修改、启停任何定义，不能读取其他成员的试算或正式结果，也不能写入正式核算批次和结果。

## 2. 身份与数据边界

`users.teacher_id` 是成员账号到成果/正式结果中 `teacher_id` 的唯一映射。未绑定该字段的成员访问个人正式结果或导出时返回 `409 TEACHER_PROFILE_NOT_LINKED`，不会以用户名或客户端参数猜测教师身份。

`workflow_runs.run_mode` 明确区分三类运行：

| 值 | 发起方 | 用途 | 与正式结果关系 |
|---|---|---|---|
| `operator` | 管理员 | 操作或调试运行 | 不写正式结果 |
| `member_trial` | 成员 | 个人暂存试算 | 不写正式批次/结果 |
| `formal` | 正式核算服务 | M5 批次执行 | 由正式结果关联 |

公共工作流运行接口不会接受该字段；服务端依据登录角色固定赋值。因此成员不能通过构造请求伪造正式运行。

## 3. 可用定义与试算

成员可调用 `GET /rule-plugins` 和 `GET /workflows`，服务端只返回状态为 `enabled` 的插件和 `active` 的工作流。访问停用或草稿定义会返回 `404`，避免泄露未发布配置。

成员通过 `POST /workflows/{workflow_id}/runs` 发起试算；产生的运行和底层计算记录由请求用户关联。成员查询运行历史或单次运行时，服务端同时校验发起人和 `member_trial` 模式，其他用户、管理员操作运行及正式运行均不可见。

## 4. 个人正式结果与导出

`GET /me/formal-calculation-results` 仅返回当前成员的教师 ID、状态为 `success` 且所属批次已 `reviewed` 的结果。响应保留结果版本、工作流运行 ID 和审核成果来源快照，支持本人追溯。

`GET /me/formal-calculation-results/export?period_id={period}` 以 CSV 导出同一受限范围的数据，并记录 `MEMBER_FORMAL_RESULTS_EXPORTED` 审计事件。接口不接收 `teacher_id`、批次或院系筛选参数，导出范围始终由当前账号决定。

## 5. 当前限制

成员暂存的删除、保留期限和管理员可见性尚未实现，因为这些规则尚未确认。本阶段保留运行记录以支持个人查看和错误排查；后续实现清理任务前必须先固化保留策略和审计要求。

Alembic 迁移 `20261020_0010` 增加账号教师映射和工作流运行模式。执行迁移后运行种子脚本时，默认成员会绑定 `SEED_USER_TEACHER_ID`（未配置时使用 `SEED_USER_USERNAME`）。
