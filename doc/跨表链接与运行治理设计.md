# NumCounts 跨表链接与运行治理设计

## 1. 范围

阶段四在不扩展身份认证、角色权限和组织数据范围的前提下，交付显式跨表链接、依赖等待、循环检测、下游失效标记、运行恢复、审计事件和运行指标。现有 `ADMIN` / `USER` 登录边界保持不变，本阶段不调整用户、角色或院系范围。

表记录仍是唯一事实来源。链接只是把目标记录的输入或输出以受控方式注入源记录的执行输入；它不允许任意查询、表达式、代码或远程地址。

## 2. 记录链接

一条 `record_links` 记录描述源计算记录如何从目标计算记录取值。

```json
{
  "source_record_id": "源记录 UUID",
  "target_record_id": "目标记录 UUID",
  "link_type": "execution",
  "input_key": "teaching_amount",
  "target_path": "output.amount"
}
```

| 字段 | 说明 |
|---|---|
| `source_record_id` | 使用链接值的计算记录 |
| `target_record_id` | 被读取的计算记录 |
| `link_type` | `data` 或 `execution` |
| `input_key` | 注入源记录执行输入的字段名 |
| `target_path` | 仅允许 `input` / `output` 及对象字段路径，例如 `output.amount` |

`data` 链接直接读取目标的 `input` 或已有 `output`。`execution` 链接要求目标记录为 `success`；目标仍在 `pending`、`waiting`、`running` 或 `stale` 时，源记录进入 `waiting`，不会自动执行目标。目标失败时，源记录写入 `RECORD_LINK_DEPENDENCY_FAILED`。

创建链接时系统拒绝自引用、运行中源记录、重复输入字段和任何有向循环，错误码为 `RECORD_LINK_SELF_REFERENCE`、`CALCULATION_ALREADY_RUNNING`、`RECORD_LINK_INPUT_EXISTS` 和 `RECORD_LINK_CYCLE`。

## 3. 执行、快照与失效

计算记录保存原始 `input`；链接只在执行开始时解析为本次输入。每个执行尝试保存：

- `input_snapshot`：合并链接值后的实际函数输入；
- `link_snapshot`：链接 ID、目标记录 ID、目标 `lock_version`、读取路径、输入键和值；
- `function_snapshot`：函数或插件的冻结调用信息。

因此，同一历史结果可以准确说明它读取了哪条目标记录、哪个版本和哪个值。

当目标记录被局部重载，或重新执行并成功提交新结果时，全部直接和间接下游结果会被标记为 `stale`，错误信息为 `DEPENDENCY_CHANGED`。旧 `output` 不会删除，便于业务复核；`stale` 记录不会自动执行，管理员应明确重载或重试需要重新核算的记录。

状态补充如下：

```text
pending / waiting → running → success / failed
目标未就绪       → waiting
链接目标改变     → stale
stale            → reload → pending
```

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/record-links` | 创建记录链接并校验循环 |
| `GET` | `/api/v1/record-links?source_record_id={id}` | 查询源记录的链接 |
| `DELETE` | `/api/v1/record-links/{id}` | 删除非运行中源记录的链接 |
| `GET` | `/api/v1/runtime/summary` | 查询记录按状态统计、总量/失败数、最早待处理与运行时间、链接数及运行尝试数 |
| `POST` | `/api/v1/runtime/recover-interrupted` | 将进程中断遗留的 `running` 记录标为失败且可重试 |
| `GET` | `/api/v1/audit-events` | 查询阶段四链接和恢复操作的审计事件 |

当前上述接口均要求现有 `ADMIN` 角色。此处并不新增角色能力；细粒度授权与组织范围控制仍挂起。

## 5. 异常恢复与监控

工作进程启动时会扫描遗留的 `running` 记录，将其和未完成尝试记录转为 `failed`，错误码为 `EXECUTION_INTERRUPTED`。管理员也可通过恢复接口手动触发相同处理，然后使用既有重试接口决定是否重算。

运行汇总返回 `pending` / `waiting` 的最早创建时间、各计算状态数量、链接总数和运行中尝试数量。生产环境仍应在平台层监控 MySQL 备份、慢查询、磁盘、服务健康检查和错误率；本阶段不在应用内执行备份或删除历史数据。

## 6. 验收场景

1. 创建教学绩效目标记录与综合绩效源记录；源记录通过 `execution` 链接读取 `output.amount`。
2. 目标仍待执行时执行源记录，源记录为 `waiting`；目标成功后再次处理待执行记录，源记录使用目标金额成功计算。
3. 尝试历史中的 `link_snapshot` 保存目标记录 ID、版本、路径和值。
4. 对目标记录执行局部重载，源记录变为 `stale` 且保留原输出；不存在自动重算。
5. 尝试创建反向链接，系统返回 `409 RECORD_LINK_CYCLE`。
6. 模拟服务中断留下 `running` 记录，执行恢复后记录与尝试均为 `failed`，并可使用既有重试流程。
